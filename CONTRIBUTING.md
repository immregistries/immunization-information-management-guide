# Contributing

Thank you for helping improve the **Immunization Information Management Guide**.

## How to propose a change

Use GitHub issues and pull requests:

- Open an **issue** for a correction, question, gap, or proposed new topic.
- Open a **pull request** when you have draft wording, source additions, or structural improvements ready for review.
- Keep pull requests focused on a single topic or closely related set of edits when practical.

## What to include

When proposing a correction or new topic, include:

- the functional question being addressed
- the relevant actors, workflow, or implementation context
- links or citations for the primary sources you relied on
- any known jurisdictional differences
- a note about whether a statement is a requirement, observed practice, interpretation, proposal, or unresolved question

## Citation expectations

Prefer primary sources whenever available, such as:

- statutes, regulations, and policy documents
- implementation guides and specifications
- official program guidance
- standards publications
- authoritative technical documentation

For each substantive claim:

- cite the specific source
- identify the most precise location available, such as section, chapter, page, or anchor
- distinguish quoted or directly supported source facts from editorial synthesis

Unpublished planning notes are not sufficient on their own for published claims. If `source-material/immunization-functional-guide-framework.md` is present in the future, treat it as planning input and verify published content against citable sources before using it.

## Editorial review

Editorial review checks whether a change:

- is within the scope of the guide
- clearly separates source facts from derived information
- distinguishes jurisdiction-specific statements from common functional descriptions
- uses the established claim labels consistently
- includes adequate citations for substantive assertions

The repository owner retains final editorial control over acceptance, wording, structure, and publication timing.

## Topic structure

New topic pages should follow the published topic template in `docs/topic-template.md`.
