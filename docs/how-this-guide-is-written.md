# How this guide is written

This guide is intended to be evidence-based, transparent about uncertainty, and explicit about what is source-backed versus editorially derived.

## Writing principles

Topic pages should:

- start from a concrete functional question
- describe actors and workflow clearly
- separate source facts from synthesis
- note observed practice without overstating uniformity
- identify jurisdictional variation where relevant
- distinguish realization details for HL7 v2 and FHIR when those sections are populated
- surface open questions instead of hiding uncertainty

## Claim labels

Use the following plain-language labels directly in Markdown:

- **Existing requirement:** a statement directly supported by a binding or governing source
- **Observed practice:** a statement about how organizations or jurisdictions appear to operate in practice
- **Interpretation:** a reasoned editorial reading derived from cited material
- **Proposal:** a suggested approach that is not presented as existing consensus or requirement
- **Unresolved:** a question, ambiguity, or area where the guide does not yet have enough evidence

## Editorial method

When adding content:

1. cite the source for each substantive factual claim
2. identify whether the statement is source fact, observed practice, or synthesis
3. note when a point varies by jurisdiction, governance model, or implementation approach
4. avoid presenting interpretation or proposal as requirement
5. leave an item marked **Unresolved** when the available evidence is incomplete

## Review expectations

Editorial review looks for:

- accurate scope
- traceable citations
- careful claim labeling
- clear separation between common patterns and local variation
- neutrality about unsettled questions
